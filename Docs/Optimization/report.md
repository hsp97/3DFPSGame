## 핵심 발견

씬 부하의 대부분은 맵이 아니라 **플레이어 모델(Ghost 50만 삼각형)과 손에 든 검(Katana 50만 삼각형)** 이다. 맵 프롭은 대부분 수십~수백 삼각형이라 LOD로 줄일 여지가 거의 없어서, 맵 프롭에는 LOD Group/Mesh LOD를 적용하지 않았다(아래 "적용하지 않은 것").

## 적용하지 않은 것과 이유

- **맵 프롭 LOD Group**: `*_LD1` / `*_LD2` 프리팹은 상세/단순 쌍이지만(예: `Cargo_container_v1_LD2close` 132 삼각형), 맵 정적 메시 전체 삼각형이 약 9만이라 얻는 이득이 측정 오차보다 작다. 기존 `FireBarrel` LODGroup 4개는 그대로 뒀다.
- **맵 FBX Mesh LOD**: 같은 이유로 생략(수백 삼각형 메시에는 이득이 작고 형태가 깨질 위험만 커짐).
- **GPU Resident Drawer / GPU Occlusion**: URP 에셋과 렌더 그래프 설정을 바꾸는 별도 작업이라 범위 밖.

## 한계와 주의

1. **Mesh LOD가 안 먹히는 시점**: V2~V4처럼 카메라가 플레이어 모델 바로 안/옆에 있으면 모델이 항상 가장 높은 LOD로 선택되고, 그림자 캐스케이드에서도 같은 모델이 그려져서 삼각형이 200만~300만으로 남는다. 이 가운데 Ghost+Katana 비중이 대부분이다(V3에서 두 렌더러를 끄면 약 7만 삼각형으로 줄어드는 것을 별도로 확인).
2. **Ghost는 스킨드 메시**라서 Mesh LOD는 삼각형 래스터 비용만 줄이고 스키닝 비용(정점 36만)은 줄이지 못한다. 스킨 가중치가 무시되므로 낮은 LOD에서 변형이 깨질 수 있어, 먼 거리/TPS 시점에서 눈으로 확인이 필요하다.
3. **좀비 LOD Group**: 컬링 임계값은 화면 높이 5%(lodBias 2 적용 시 약 70m)다. 이번 측정에는 70m 밖 좀비가 없어서 효과를 못 봤다. 실제 플레이에서 좀비가 사라지는 거리가 거슬리면 임계값을 조정하면 된다.
4. **측정 신뢰도**: 에디터 모드 측정이고, 최적화 후반에 같은 설정으로 재측정한 값이 모든 시점에서 일정하게 높게 나오는 구간이 있었다(배치 약 +140, SetPass 약 +27, 그림자 캐스터 약 +100, 삼각형 약 +15만). 이것은 최적화와 무관한 에디터 쪽 추가 렌더링(다른 창/뷰의 렌더링 등으로 추정, 원인 미확인)이며 FX 오브젝트를 꺼도 일부 시점에서만 사라졌다. 그래서 Mesh LOD 이후 수치는 3회 측정 중 최소값을 썼다(오염은 값을 올리기만 하므로 최소값이 실제에 가깝다). 기준선은 1회 측정이지만 미니맵 켬/끔 두 샘플이 서로 거의 같아 깨끗한 상태로 보인다. 배치 100 이하, SetPass 10 이하의 차이는 오차 범위로 보는 게 안전하다.
5. 시간(ms)은 에디터에서는 신뢰할 수 없어 기록하지 않았다. 실제 프레임 시간 비교는 빌드나 플레이 모드 프로파일링이 필요하다.
6. **플레이 모드 확인은 하지 못했다**(MCP 플레이 루프가 자주 멈춤). 오클루전 팝핑(가려진 물체가 갑자기 나타나는 현상), Ghost/Katana 낮은 LOD 모양, 좀비 컬링은 직접 플레이로 확인해야 한다.

## 후속 제안 (효과가 큰 순)

1. **Ghost/Katana 원본 폴리곤 줄이기**: 두 모델이 각각 50만 삼각형이다. 모델링 도구에서 1만~5만 삼각형으로 줄이면 모든 시점의 기본 비용이 내려가며, Mesh LOD 한계(1번)를 근본적으로 해결한다.
2. **Katana 그림자 캐스팅 끄기**(1인칭에서 손에 든 검 그림자는 거의 안 보임): 그림자 캐스케이드 4번 분량의 50만 삼각형이 사라진다.
3. 플레이어 모델에 `Renderer.meshLodSelectionBias`를 조정해 가까운 거리에서도 낮은 LOD를 쓰게 하기(시도 결과는 위 측정 오염 때문에 신뢰할 수 없어서 폐기. 오염 없는 환경에서 다시 측정 필요).
4. GPU Resident Drawer + GPU Occlusion 비교 측정.
